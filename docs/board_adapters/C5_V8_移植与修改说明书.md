## 1. 硬件与引脚（Marauder V8 / ESP32-C5）

| 信号 | GPIO | 说明 |
|---|---|---|
| TFT_MISO | 5 | 经 GPIO 矩阵映射到 FSPI MISO |
| TFT_MOSI | 1 | 经 GPIO 矩阵映射到 FSPI MOSI |
| TFT_SCLK | 9 | 经 GPIO 矩阵映射到 FSPI CLK |
| TFT_CS | 24 | 软件片选 |
| TFT_DC | 10 | 数据/命令 |
| TFT_RST | 0 | 复位 |
| TFT_BL | 23 | 背光（LEDC PWM） |
| TOUCH_CS | 4 | XPT2046 片选（与 TFT 共享 MISO/MOSI/SCLK） |
| SD_CS | 6 | SD 卡片选（与 TFT 共享 MISO/MOSI/SCLK） |
| I2C_SDA / SCL | 8 / 26 | 电池电量计 |
| GPS_TX / RX | 13 / 14 | |
| ACT_LED | 28 | |

**关键结论**：本板 TFT、触摸、SD 三设备共用一条 FSPI（SPI2）总线。
ESP-IDF 中 SPI2 的原生 IOMUX 引脚为 `MISO=2 / CLK=6 / MOSI=7 / CS=10`，
当前使用的 `SCLK=9 / MOSI=1 / MISO=5` 需经 GPIO 矩阵路由，但仍走硬件 SPI
（非 bit-bang），无需软件模拟时序。

## 2. 系统架构：三设备共享一条 SPI 总线

```
                ┌──────────── SPI2 (FSPI) ────────────┐
                │  SCLK=9   MOSI=1   MISO=5           │
   ILI9341 ──CS24┤                                     ├── XPT2046 ──CS4
   (10 MHz 写)   │                                     │   (2.5 MHz)
   (20 MHz 读)   │                                     │
   SD 卡  ──CS6  ┘                                     └── 同总线，独立事务
```

隔离方式：**CS + SPI 事务（transaction）**，各设备在事务中声明自己的时钟频率，
互不污染：

| 设备 | 片选 | 频率来源 | 事务位置 |
|---|---|---|---|
| ILI9341 写 | GPIO24 | `SPI_FREQUENCY` = 10 MHz | `begin_tft_write()` / `end_tft_write()` |
| ILI9341 读 | GPIO24 | `SPI_READ_FREQUENCY` = 20 MHz | `begin_tft_read()` / `end_tft_read()` |
| XPT2046 触摸 | GPIO4 | `SPI_TOUCH_FREQUENCY` = 2.5 MHz | `begin_touch_read_write()` / `end_touch_read_write()` |
| SD 卡 | GPIO6 | `card->frequency`（默认 4 MHz） | SD 库内部 `beginTransaction` |

要点：
1. 三设备必须共用**同一个 `SPIClass` 实例（全局 `SPI`）**，事务锁才能互斥；
2. 总线由**第一个使用者**按正确引脚 `begin()`；`SPIClass::begin()` 在总线已启动时
   直接返回 `true`，**不会重新绑定引脚**，所以引脚必须一次配好；
3. 显示驱动不再 bit-bang，焊盘归属 SPI 外设，此时再写 GPIO 输出寄存器是无效的，
   两种方式**不可混用**。

## 4. 修复记录

### 4.1 白屏 + SD 无法初始化
- 根因：硬件 SPI 的 `begin()` 被重复/冲突调用，引脚归属混乱；SD 侧又用了独立
  `SPIClass` 副本，导致总线未正确启动。
- 最终方案：**统一使用全局 `SPI`**，由 SD 初始化阶段先 `begin(9,5,1,-1)`，显示驱动
  随后 `begin()` 只是幂等空操作；CS/DC/TOUCH_CS 全部用 GPIO 控制。
- 相关代码：`SDInterface::initSD()` 的 `HAS_C5_SD` 分支。

### 4.2 触摸失效
- 根因 1：库内判断用了 `MARAUDER_V8`，而 TFT_eSPI 库编译时**没有**定义该宏，
  分支变成死代码，实际走了 `spi.transfer16()` 的流水线式读取。
- 根因 2：X/Y 命令字写反。正确值：**X = 0xD3（A=101）、Y = 0x93（A=001）**，
  Z1 = 0xB3、Z2 = 0xC3，PD=11。
- 根因 3：一次 CS 内流水线读会让下一次转换未完成。改为**每通道独立读**：
  控制字节 + 2 个空字节（共 24 时钟），结果 `((hi<<8)|lo) >> 3`。
- 结论：库内条件必须写 `#if defined(CONFIG_IDF_TARGET_ESP32C5)`，不能用工程宏。

### 4.3 屏幕刷新慢
演进与实测：

| 方案 | 每 bit 写寄存器次数 | fillScreen 耗时 | 速率 |
|---|---|---|---|
| bit-bang（set/clear 三写） | 3 | 771821 µs | 199 KB/s |
| bit-bang（GPIO_OUT 直写合并） | 2 | 559683 µs | 274 KB/s |
| 硬件 SPI 10 MHz（当前） | — | 约 120~140 ms（理论 123 ms） | 约 1.1~1.25 MB/s |

- bit-bang 上限：约 0.46 µs/bit ≈ 110 个 CPU 周期/bit，单次 APB 寄存器写约 50 周期，
  已无可压缩空间。
- 改为硬件 SPI 后 CPU 不再逐位翻转，`pushBlock` / `pushPixels` 走 FIFO 批量发送。

### 4.4 其它
- `tftbench` 显示 0 KB/s：整数除法顺序错误，已修正。
- `'TFT_BL' was not declared`：V8 引脚块补上 `#define TFT_BL 23`。

### 6.2 `Processors/TFT_eSPI_ESP32_C5.c` 批量写

```cpp
void TFT_eSPI::pushBlock(uint16_t color, uint32_t len) {
  uint8_t buf[2] = { (uint8_t)(color >> 8), (uint8_t)(color & 0xFF) };
  spi.writePattern(buf, 2, len);          // FIFO 批量填充
}

void TFT_eSPI::pushSwapBytePixels(const void* data_in, uint32_t len) {
  spi.writeBytes((const uint8_t*)data_in, len * 2);   // 高字节在前
}

void TFT_eSPI::pushPixels(const void* data_in, uint32_t len) {
  if (_swapBytes) { spi.writeBytes((const uint8_t*)data_in, len * 2); return; }
  const uint16_t *data = (const uint16_t*)data_in;
  uint8_t buf[128];
  while (len) {                            // 低字节在前，64 像素一批
    uint32_t n = len > 64 ? 64 : len;
    for (uint32_t i = 0; i < n; i++) {
      uint16_t c = data[i];
      buf[i * 2] = (uint8_t)(c & 0xFF);
      buf[i * 2 + 1] = (uint8_t)(c >> 8);
    }
    spi.writeBytes(buf, n * 2);
    data += n; len -= n;
  }
}
```

## 8. 已知约束与坑

1. **库内未定义 `MARAUDER_V8`**：TFT_eSPI 库编译时该宏不存在，库内条件一律用
   `#if defined(CONFIG_IDF_TARGET_ESP32C5)`。
2. **SD 库在 C5 上跳过 `spi.begin()`**：必须由 `SDInterface` 先 `begin()`；且要传
   **全局 `SPI`**，不能用 `SPIClass` 副本（副本有自己的事务锁，等于没有互斥）。
3. **`SPIClass::begin()` 幂等**：已启动时直接返回，不会重新绑定引脚 —— 谁先调用谁决定引脚。
4. **不可混用 bit-bang 与硬件 SPI**：焊盘归属外设后 GPIO 写无效。
5. **工程目录中的 `esp32_marauder\TFT_eSPI`** 是早期 bit-bang 的陈旧副本，构建**不会**使用它
   （编译产物 `.d` 指向全局库）；不要改错地方，也不要把它当成库依赖。
6. **触摸时钟 ≤ 2.5 MHz**，XPT2046 对速率敏感；命令字必须 X=0xD3、Y=0x93。
7. **`HAS_PSRAM` 必须保持关闭**（C5 无 PSRAM）。
8. 屏幕读写频率若遇花屏/乱码：先把 `SPI_FREQUENCY` 降到 `8000000`；稳定后可尝试
   `20000000` 提升约一倍（长排线时可能出噪点）。
9. `tftbench` 的 KB/s 计算必须一次性完成（见 3.2）。
10. `SD_CS` 在 `configs.h` 中存在两处定义（显示区与 SD 定义区），以 SD 定义区为准。

## 10. 回退方案

若硬件 SPI 在实机上出现白屏/花屏且降频无效：
1. 临时把 `User_Setup.h` 的 `SPI_FREQUENCY` 降到 `8000000` 再验证一次；
2. 仍失败则回退到 bit-bang 方案（`TFT_eSPI_ESP32_C5.h/.c` 的 GPIO 寄存器直写版 +
   `Touch.cpp` 用 `tft_c5_xfer_byte()` + SD 库 bit-bang 后端），
   该方案已在实机验证可达 274 KB/s（`559683 µs / 76800 px`）。
